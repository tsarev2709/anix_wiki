# Как редактировать wiki

Wiki полезна, только если команда доверяет её актуальности. Хорошая правка делает действие яснее, а границу уверенности — честнее.

## Самый быстрый способ

На любой странице нажать **«Предложить правку»**. GitHub откроет исходный Markdown-файл.

## Перед созданием страницы

1. Найдите тему через поиск.
2. Проверьте, нельзя ли усилить существующую страницу.
3. Определите рабочий вопрос, на который отвечает материал.
4. Выберите тип: how-to, reference, explanation или learning path.
5. Начните с короткого ответа и действия.

## Стандарт знания

У страницы должны быть:

- понятный читатель;
- ситуация использования;
- короткий ответ сверху;
- ограничения;
- следующий шаг;
- связанные страницы;
- источник для внешних фактов;
- дата или событие, после которого нужна новая проверка.

## Статус утверждения

Используйте явную маркировку:

- **Подтверждено** — первичный источник, договорённость, аналитика.
- **Со слов клиента** — результат из обратной связи.
- **Гипотеза** — версия для теста.
- **Требует проверки** — факт мог устареть.

## Что нельзя публиковать

Репозиторий публичный. Не добавляйте:

- персональные данные;
- закрытые финансы и внутреннюю себестоимость;
- клиентские контакты;
- договоры и коммерческие условия под NDA;
- необъявленные проекты;
- медицинские / юридические документы клиента;
- книги и отчёты без права на распространение;
- токены, пароли, ключи и конфигурацию доступа.

## Definition of done

Человек, которого не было в исходном разговоре:

1. понимает ответ;
2. видит уровень доказательства;
3. может выполнить следующий шаг;
4. не нуждается в устном переводчике;
5. не получит опасного обещания из неоднозначной фразы.

## Ритм обслуживания

- после нового вопроса клиента — обновить FAQ;
- после проекта — добавить доказательство и ограничение;
- после проигранной сделки — обновить критерии / возражения;
- раз в квартал — проверить продукты, нормы, цены и внешние ссылки;
- устаревшее не удалять молча: пометить или заменить с объяснением.
