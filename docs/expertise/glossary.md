# Словарь нейроанимации Anix

<span class="anix-kicker">Технологии × драматургия × бизнес</span>

Словарь нужен не для демонстрации терминов. Он помогает быстро объяснить клиенту, **что именно мы проектируем, чем управляем и за что он платит**.

## Базовое определение

**Нейроанимация** — производство анимационного или гибридного видео, в котором генеративные и ML-модели участвуют в создании изображений, движения, голоса, звука, вариантов или автоматизации операций, а человек удерживает задачу, драматургию, режиссуру, art direction, фактическую точность и финальный QC.

**Не равно:** «ролик целиком сделал один prompt». В клиентском производстве ценность чаще находится в системе решений между brief и delivery.

## 1. Технологическая грамотность

| Термин | Коротко | Как объяснить клиенту |
|---|---|---|
| AI-native production | процесс изначально спроектирован с AI-инструментами | не добавляем «нейроэффект» в конце; выбираем pipeline на старте |
| AI-only | попытка решить весь проект одной генерацией | подходит для эксперимента, редко — для сложного согласуемого master |
| Multi-model pipeline | разные модели решают разные операции | модель движения не обязана быть лучшей для дизайна, речи или upscale |
| Foundation model | крупная базовая модель общего назначения | двигатель, который ещё нужно встроить в процесс |
| Diffusion model | семейство генеративных моделей для синтеза медиа | источник вариантов, а не гарантия финального кадра |
| Text-to-image | изображение из текстовой инструкции | быстро исследуем образы и styleframes |
| Image-to-image | новое изображение на основе референса | управляем композицией и стилем точнее чистого текста |
| Text-to-video | видео из описания | полезно для поиска шота; контроль зависит от модели |
| Image-to-video | движение из заданного кадра | лучше удерживает art direction, но может деформировать детали |
| Video-to-video | преобразование существующего видео | сохраняем движение/постановку, меняем визуальный слой |
| Reference-to-video | генерация с опорой на героя, предмет или стиль | повышает шанс consistency, не отменяет QC |
| Prompt | инструкция модели | один из управляющих документов, не сценарий фильма |
| Negative prompt | описание того, чего следует избегать | снижает часть ошибок, но не даёт абсолютного запрета |
| Seed | стартовое значение случайности | помогает повторять направление в пределах версии модели |
| Latent space | внутреннее пространство признаков модели | объясняет, почему небольшое изменение резко меняет результат |
| Inference | получение результата от обученной модели | то, что пользователь обычно называет генерацией |
| Fine-tuning | дополнительное обучение под задачу | полезно при повторяемой системе, но требует данных и контроля |
| LoRA | компактная адаптация модели под образ/стиль | вариант удерживать визуальную специфику в open-model pipeline |
| ControlNet / controls | управление позой, глубиной, контуром и композицией | уменьшаем случайность через структуру кадра |
| ComfyUI | node-based среда для генеративных workflow | позволяет собирать и воспроизводить сложные цепочки |
| API | программный доступ к сервису | нужен для автоматизации и массовых версий |
| Checkpoint | сохранённая версия весов модели | влияет на стиль, возможности и воспроизводимость |
| Version pinning | фиксация версии модели и настроек | защищает проект от внезапного изменения сервиса |
| Provenance | происхождение исходников и действий над ними | важно для прав, доверия и расследования ошибок |
| C2PA | стандарт данных о происхождении цифрового контента | один из способов маркировать историю медиа |

## 2. Качество AI-видео

| Термин | Коротко | Продажный смысл |
|---|---|---|
| Consistency | постоянство героя, объекта и мира между кадрами | одна из главных причин, почему серия сложнее одного шота |
| Temporal consistency | стабильность деталей во времени внутри шота | меньше мерцания, «плавления» и случайных изменений |
| Character bible | утверждённая система вида, пропорций и поведения героя | база для маскота и серийного производства |
| Styleframe | ключевой кадр, задающий визуальный язык | дешёвая точка согласования до анимации |
| Keyframe | опорный кадр движения или сцены | позволяет управлять началом, концом и акцентами |
| Interpolation | создание промежуточных кадров | сглаживает движение; не создаёт драматургию |
| Frame rate / FPS | число кадров в секунду | влияет на пластику и техтребования |
| Artifact | нежелательная ошибка генерации | деформация, лишняя деталь, неверная физика, текст или anatomy |
| Flicker | мерцание деталей между кадрами | типичный temporal-дефект, заметный после монтажа |
| Hallucination | убедительно выглядящая, но неверная деталь | критично для медицины, техники и безопасности |
| Upscale | увеличение разрешения и детализации | не исправляет смысловую ошибку |
| Inpainting | локальная перегенерация участка | лечит отдельный дефект без пересборки кадра |
| Outpainting | расширение кадра за исходные границы | помогает сделать новые aspect ratio |
| Rotoscoping | покадровое выделение объектов/масок | соединяет генерацию, съёмку и графику |
| Compositing | сборка нескольких слоёв в финальный кадр | там часто рождается управляемость AI-материала |
| Clean-up | ручное исправление ошибок | скрытая, но важная часть профессионального результата |
| Lip sync | синхронизация артикуляции и речи | требует проверки языка, эмоции и крупных планов |
| Voice clone | синтетический голос по образцу | только с разрешением и понятным контуром прав |
| Native audio | звук, созданный моделью вместе с видео | быстро для идеи; master часто требует отдельного sound design |
| Master | главная утверждённая версия | источник адаптаций, а не случайный экспорт |
| Delivery package | полный комплект выдачи | master, форматы, субтитры, обложки, исходники по договору |

## 3. Драматургия и режиссура

| Термин | Значение | Проверочный вопрос |
|---|---|---|
| Аудитория | группа с общим контекстом и мотивацией | кто должен изменить понимание или действие? |
| Коммуникационная задача | изменение, которое должен вызвать материал | что станет иначе после просмотра? |
| Тема | о чём история на уровне смысла | какую мысль зритель унесёт? |
| Контртема | сила, сопротивляющаяся теме | почему герой не действует правильно сейчас? |
| Герой | носитель выбора и изменения | чьими глазами мы понимаем проблему? |
| Цель героя | желаемый результат внутри истории | чего он пытается добиться? |
| Конфликт | препятствие между героем и целью | что делает историю, а не иллюстрацию? |
| Ставка | цена успеха или ошибки | почему зрителю не всё равно? |
| Перипетия | изменение направления действия | где появляется новая причинность? |
| Арка | изменение героя или понимания | чем финал отличается от начала? |
| Beat | минимальная смысловая единица действия | один момент — одно изменение |
| Hook | первый элемент, создающий внимание | почему смотреть следующие пять секунд? |
| Setup | ввод контекста и правил мира | сколько действительно нужно объяснить? |
| Payoff | отдача подготовленного элемента | что зритель получает за внимание? |
| CTA | конкретный следующий шаг | что сделать после просмотра? |
| Logline | одно предложение о герое, цели и препятствии | можно ли понять ролик до сценария? |
| Treatment | краткое описание истории и формы | согласуем идею до детализации |
| Экспликация | режиссёрская логика исполнения | почему такие планы, ритм, цвет и звук? |
| Сценарий | текстовая модель действия и структуры | что происходит и почему? |
| Раскадровка | последовательность ключевых кадров | как сценарий превращается в визуальные решения? |
| Animatic | раскадровка во времени с черновым звуком | работает ли ритм до дорогого production? |
| Mise-en-scène | организация пространства, объектов и действия | куда направлено внимание? |
| Планы | общий, средний, крупный и детали | какую информацию несёт масштаб? |
| Монтажная фраза | последовательность планов с единым смыслом | возникает ли мысль из сопоставления кадров? |
| Ритм | длительность, движение, звук и паузы | выдерживает ли материал внимание и ясность? |
| Визуальная метафора | объяснение абстрактного через образ | помогает ли она понять, а не только украшает? |
| Маскот | повторяемый персонаж-носитель бренда/правил | выдержит ли он серию и разные каналы? |
| Тональность | эмоциональный режим коммуникации | допустимы ли юмор, тревога, эпика, ирония? |

## 4. Бизнес и продуктовая экспертиза

| Термин | Значение | Как применять |
|---|---|---|
| Use case | конкретная ситуация применения | продавать не «ролик», а решение в ситуации |
| Trigger | событие, создающее срочность | запуск, конференция, аудит, инцидент, пилот |
| JTBD | работа, для которой клиент нанимает решение | что он пытается добиться, а не какой формат просит? |
| Value proposition | ценность для выбранной аудитории | один результат, одна причина верить |
| Scope | согласованный объём и границы | что входит, что не входит, кто даёт исходники |
| Deliverable | конкретный передаваемый результат | master 60 сек, 3 cut-down, 2 aspect ratio и т.д. |
| KPI | метрика бизнес-результата | продажи, пилоты, понимание, соблюдение, время запуска |
| Leading metric | ранний показатель | досмотры, ответы, повторные встречи, прохождение |
| Lagging metric | итоговый показатель | сделка, травматизм, внедрение, удержание |
| Baseline | состояние до запуска | без него сложно честно оценить изменение |
| Attribution | связь результата с воздействием | ролик редко является единственной причиной |
| A/B test | сравнение вариантов в одинаковых условиях | проверяет влияние asset на конверсию |
| Sales enablement | система материалов и практик для продавца | единое объяснение, кейсы, версии, follow-up |
| Content atomization | разложение master на набор активов | один production превращается в десятки касаний |
| Campaign | связанная система материалов во времени | не набор файлов, а последовательность контактов |
| Content system | правила, assets и шаблоны для продолжения | снижает стоимость и срок следующих выпусков |
| Pilot | ограниченная проверка в реальном контексте | первый безопасный scope с наблюдаемой метрикой |
| Proof point | доказательство отдельного тезиса | кейс, цифра, процесс, демо, источник |
| ROI | финансовая отдача относительно затрат | считать только при доступных данных |
| Total cost of ownership | полная стоимость владения | создание + обновления + версии + размещение |
| Change request | новое требование после фиксации scope | оценивается отдельно, а не маскируется под правку |
| Iteration | цикл единого пакета комментариев | уменьшает хаос согласующих |
| Acceptance criteria | проверяемые условия приёмки | что должно быть истинно для утверждения этапа? |
| LTV | ценность клиента за всё время | продолжение важнее разовой максимальной сделки |

## 5. Отраслевые термины

| Контур | Термины, которые продавец должен знать |
|---|---|
| Pharma | HCP, patient communication, MoA, claim, indication, packshot, Medical Affairs, Regulatory, Legal review |
| MedTech | clinical workflow, pilot, integration, validator, procurement, adoption, evidence, data security |
| HSE | ОТиПБ, hazard, risk, control, near miss, incident, permit-to-work, toolbox talk, critical rule |
| L&D / HR | onboarding, learning objective, microlearning, scenario-based learning, retrieval practice, transfer, LMS, completion |

## 6. Как ролик работает для разных функций

| Функция клиента | Работа ролика | Наблюдаемое действие |
|---|---|---|
| HSE | показать риск, развилку и правильное действие | обсуждение кейса, распознавание hazard, выполнение правила |
| Фарма-маркетинг | сделать препарат и сообщение узнаваемыми | запоминание, переход, контакт, участие в кампании |
| Medical Affairs | визуализировать утверждённую научную модель | корректное понимание механизма/данных |
| Отдел продаж | дать единое объяснение и повод продолжить | ответ, встреча, демо, пилот, пересылка внутри клиента |
| HR | объяснить EVP, культуру или изменение | отклик кандидата, завершение onboarding, действие сотрудника |
| Корпоративный университет | встроить visual scenario в обучение | решение задачи, проверка, перенос в работу |
| Product / B2B | показать workflow и ценность продукта | понятный use case и следующий коммерческий шаг |

## Статус знания

- <span class="anix-badge anix-badge--fact">Подтверждено</span> есть первичный источник или наблюдаемый факт.
- <span class="anix-badge anix-badge--reported">Со слов клиента</span> результат сообщён, но не проверен независимо.
- <span class="anix-badge anix-badge--hypothesis">Гипотеза</span> версия для проверки действием.
- **Устарело** — факт нельзя использовать без новой проверки.

:::
