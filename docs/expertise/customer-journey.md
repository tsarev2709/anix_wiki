# Путь клиента Anix

<span class="anix-kicker">От триггера до контент-системы</span>

Путь клиента состоит из двух связанных процессов: **как клиент покупает Anix** и **как материал Anix работает внутри процесса клиента**. Если вторую часть не спроектировать, можно идеально произвести невостребованный файл.

## 1. Коммерческий путь

| Этап | Новый факт, который нужен | Действие Anix | Выход |
|---|---|---|---|
| Research | выбран account, роль и вероятный триггер | изучить бизнес, кампании, вакансии, события, контент | гипотеза, не шаблонное письмо |
| Первое касание | клиент признаёт релевантность | кейс/референс + точный вопрос | ответ или интро |
| Qualification | есть ситуация, владелец, срок и ценность | проверить боль, альтернативы, процесс решения | go / nurture / no fit |
| КЭВ / discovery | понятны аудитория, действие и ограничения | разобрать последний реальный эпизод | карта задачи |
| Roadmap / solution | выбран первый безопасный scope | 2–3 варианта с trade-offs | направление и бюджетный коридор |
| Proposal | понятны deliverables, этапы, роли и цена | КП + production plan + assumptions | согласование |
| Contract / brief | закрыты legal и исходные данные | договор, ТЗ, график, аванс | старт |
| Production | решения утверждаются до дорогой стадии | прототипы, итерации, единый feedback owner | master |
| Delivery / launch | материал встроен в канал | версии, handoff, рекомендации по применению | использование |
| Measurement | есть данные после запуска | собрать baseline/метрики/обратную связь | кейс и выводы |
| Expansion | доказана первая ценность | серия, маскот, библиотека, программа | повторная продажа |

## 3. Стандарты хорошего сервиса

- один владелец коммуникации с каждой стороны;
- письменная фиксация решений и assumptions;
- единый пакет feedback вместо противоречивых комментариев;
- ранние дешёвые формы проверки;
- stage-gates и понятная цена позднего изменения;
- клиент видит следующий шаг и срок ответа;
- проблемы поднимаются до срыва, а не после;
- приёмка привязана к критериям, а не к «нравится/не нравится».

## 4. Как не работаем

- не начинаем дорогой production без утверждённого смысла;
- не принимаем medical/HSE-факты «из головы»;
- не обещаем неограниченные правки без критерия;
- не превращаем бесплатный пресейл в готовую кампанию;
- не утверждаем, что один asset гарантирует бизнес-метрику;
- не делаем «для всех аудиторий» без архитектуры версий;
- не молчим о риске срока, прав или consistency.

## 5. Что измерять по вертикалям

| Вертикаль | До запуска | Ранние метрики | Итоговые метрики |
|---|---|---|---|
| B2B / sales | reply rate, conversion to meeting, time to explain | пересылки, встречи, demo/pilot requests | pipeline influence, win rate при корректном дизайне измерения |
| Pharma | baseline знания/восприятия, медиаплан | досмотры, engagement, переходы, recall | утверждённая campaign metric; не приписывать одному ролику |
| HSE | знание правила, near miss/observations, выполнение | распознавание hazards, ответы, участие | поведение и incident data в системе мер |
| L&D | baseline performance | completion, retrieval, scenario decisions | transfer в работу, supervisor observation |
| HR | baseline откликов/понимания EVP | просмотры, заявки, прохождение onboarding | quality/retention при достаточном горизонте |

## 6. Триггеры по вертикалям

| Фарма | HSE | MedTech | HR / L&D | Сложный B2B |
|---|---|---|---|---|
| запуск / новый цикл | аудит / инцидент | конференция / пилот | onboarding / трансформация | выставка / новый сегмент |
| HCP-мероприятие | остановочный ремонт | релиз | обязательное обучение | зависшая воронка |
| новый препарат | выход подрядчиков | новая клиника | найм / EVP | основатель — единственный demo |

## 7. Definition of Done

Проект завершён не на фразе «ролик красивый», а когда:

- deliverables соответствуют ТЗ и acceptance criteria;
- факты и обязательные элементы утверждены владельцами;
- технические версии проверены;
- клиент знает, где и как использовать материалы;
- источники, версии и права переданы по договору;
- создана дата разбора результата;
- change request и незакрытые гипотезы перечислены отдельно.
