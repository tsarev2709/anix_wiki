# Измерение эффекта: от просмотра к KPI

<span class="anix-kicker">Measurement playbook</span>

Материал нельзя оценивать отдельно от места, аудитории и следующего действия. До сценария Anix и клиент заполняют короткий **measurement contract**: функция asset, baseline, главная метрика, источник данных, владелец и дата проверки.

## Лестница доказательства

| Уровень | Что измеряем | Примеры | Сила вывода |
|---|---|---|---|
| 1. Output | что выпущено и доставлено | master, версии, срок, охват | производство состоялось |
| 2. Attention | был ли контакт | play rate, досмотр, dwell time | материал заметили |
| 3. Understanding | что поняли | pre/post, правильный пересказ, ошибки | сообщение усвоено |
| 4. Action | что сделали | CTA, meeting, demo, safe choice | действие связано с задачей |
| 5. Business outcome | что изменилось в системе | pipeline, time-to-competence, incident rate | нужны контроль факторов и более длинный период |

AMEC рекомендует не останавливаться на outputs и отслеживать outcomes: понимание, отношение, намерение и действие. Для обучения полезна та же логика в модели Kirkpatrick: Reaction → Learning → Behavior → Results.

## Measurement contract: шаблон

| Поле | Что записать |
|---|---|
| Аудитория | одна конкретная роль / группа |
| Ситуация | где и когда человек увидит материал |
| Нужное действие | один следующий наблюдаемый шаг |
| Главная метрика | одна метрика принятия решения |
| Диагностические | 2–3 показателя, объясняющие результат |
| Baseline | прежний материал, период или текущий процесс |
| Источник | LMS, CRM, web analytics, тест, наблюдение, интервью |
| Владелец данных | конкретная должность со стороны клиента |
| Период | когда первый и итоговый check-in |
| Другие изменения | размещение, бюджет, команда, процесс, сезонность |
| Решение | stop / revise / scale и порог для каждого |

## Готовые схемы по продуктам

### Product explainer / B2B / MedTech

| Этап | Основная метрика | Диагностические |
|---|---|---|
| Первое касание | reply / meeting conversion | play, completion, CTA click |
| После встречи | time-to-next-step | новые участники, пересылка, повторные вопросы |
| Demo | demo-to-pilot | понимание workflow, objections before/after |
| Продажи | asset-assisted conversion | seller adoption, тип сделки, источник лида |

**Минимальный тест:** прежнее письмо или deck против письма с asset на сопоставимых сегментах. Не объявлять причинность, если одновременно изменились offer, список и продавец.

### Фарма

| Задача | Метрика | Важная оговорка |
|---|---|---|
| HCP digital | completion, engagement, следующий контент | метрика должна быть утверждена владельцем канала |
| Field force | использование материала, message recall | не путать активность поля с medical impact |
| Конференция | целевые контакты и qualified follow-up | сканы без квалификации — слабый показатель |
| Производство | срок, возвраты, reuse утверждённых активов | отделять новые claims от ошибок production |
| Medical education | понимание и полезность | medical / regulatory задают допустимые формулировки |

### HSE

| Уровень | Метрика | Метод |
|---|---|---|
| Доставка | completion по целевой группе | LMS / журнал / QR-доступ |
| Понимание | прирост правильных решений | pre/post или параллельные группы |
| Поведение | соблюдение одного критического действия | стандартизированное наблюдение |
| Процесс | время допуска, повторные вопросы | журнал HSE / интервью |
| Система | near misses, сроки корректирующих действий | существующий safety dashboard |
| Итог | incidents / severity / downtime | длинный период, контроль других вмешательств |

NIOSH подчёркивает: обучение может улучшать знания, навыки, установки и поведение, но само по себе не доказано как достаточная причина снижения травм. Это граница коммерческого обещания и одновременно аргумент за более честный pilot design.

### Корпоративное обучение и онбординг

| Уровень Kirkpatrick | Что спросить | Метрика |
|---|---|---|
| Reaction | полезно ли для реальной работы | relevance, confidence, completion |
| Learning | что человек теперь знает / умеет выбрать | pre/post, scenario accuracy |
| Behavior | применил ли на рабочем месте | observation, manager check, error pattern |
| Results | что изменилось для функции | time-to-competence, quality, cycle time |

## Формулы без ложной точности

**Прирост понимания, п.п.**

$$\Delta C = C_{after} - C_{before}$$

**Конверсия в следующий шаг**

$$CR = \frac{\text{целевые действия}}{\text{подходящие получатели}} \times 100\%$$

**Использование asset продавцами**

$$Adoption = \frac{\text{активные пользователи asset}}{\text{продавцы целевой группы}} \times 100\%$$

**Экономия времени процесса**

$$Hours\ saved = (T_{before} - T_{after}) \times N$$

ROI считать только вместе с клиентом, если согласованы денежные эффекты и полная стоимость. Просмотры нельзя произвольно переводить в выручку.

## Выбор дизайна

| Условия | Подход |
|---|---|
| есть достаточный поток | A/B на сопоставимых сегментах |
| нельзя делить аудиторию | before/after с фиксацией других изменений |
| несколько объектов | phased rollout / matched sites |
| мало сделок | mixed evidence: CRM + интервью + разбор звонков |
| только один event | заранее зафиксированный follow-up funnel |
| высокий safety-риск | пилот + экспертная валидация + наблюдение, не только тест |

## Что записать в кейс

1. baseline и период;
2. аудиторию и размер выборки / число сделок;
3. точный intervention;
4. канал и CTA;
5. результат и источник данных;
6. другие изменения;
7. кто сообщает цифру: Anix, клиент или поставщик;
8. что кейс не доказывает.

## Красные флаги

- «рост на 300%» без абсолютных чисел;
- сравнение разных аудиторий и периодов;
- attributed / influenced pipeline выдают за выручку, созданную роликом;
- completion называют знанием или поведением;
- снижение инцидентов приписывают одному модулю;
- vendor case пересказывают как независимое исследование;
- выбирают метрику после получения результата.
