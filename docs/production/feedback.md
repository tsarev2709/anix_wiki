# Правки и согласования

Цель процесса правок — улучшить результат, не превращая проект в соревнование несовместимых мнений.

## Правило одного пакета

Клиент назначает человека, который:

1. собирает комментарии всех сторон;
2. убирает дубли;
3. разрешает противоречия;
4. отмечает обязательное и предпочтительное;
5. отправляет один согласованный пакет.

## Формат хорошего комментария

**Где → что не работает → почему → что должно измениться.**

Пример:

> 00:18, фраза «полностью безопасен». Не проходит medical, потому что утверждение абсолютное. Использовать согласованную формулировку из строки 7 claims-table.

Слабый вариант: «что-то тут не нравится».

## Приоритеты

| Уровень | Пример | Действие |
|---|---|---|
| P0 — факт / право | неверный claim, логотип, раскрытие данных | исправить до показа |
| P1 — задача | сцена ведёт к неверному выводу | исправить в итерации |
| P2 — качество | артефакт, ритм, читаемость | исправить по критериям |
| P3 — предпочтение | «хочется другой оттенок» | оценить влияние и scope |

## Что меняет scope

- новая аудитория;
- новый главный тезис;
- смена концепции после утверждения;
- новые сцены или персонажи;
- новый язык / формат / длительность;
- замена исходной фактуры;
- возврат на уже принятую стадию;
- новые согласующие с новыми требованиями.

## Точки согласования

1. фактура и claims;
2. концепция;
3. сценарий;
4. раскадровка;
5. ключевые тестовые кадры;
6. черновой монтаж;
7. финал.

Не каждый проект требует всех точек. Но пропуск раннего согласования не делает позднюю переделку бесплатной.

## Ответ на противоречивые правки

> Сейчас комментарии A и B ведут к разным решениям. Если выбираем A, сохраняем [эффект], но теряем [ограничение]. Если B — наоборот. Нужен единый выбор владельца результата до продолжения производства.
